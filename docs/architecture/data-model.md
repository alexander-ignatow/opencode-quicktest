# Data model

Storage is PostgreSQL, accessed through Drizzle ORM with generated, committed SQL migrations (`apps/api/drizzle/`). Field rules — required or optional, lengths, ranges — are specified in `docs/requirements.md` §6; this file records the shape they take in the database and is kept in sync with it.

## Identity and keys

- Every table has a surrogate primary key `id`: `text`, 12 characters, lowercase base36 (`0-9a-z`), generated in code with `nanoid`'s `customAlphabet`. Foreign keys are the same type. Ids are internal: no URL, no UI text and no API of this app exposes them.
- **No natural keys.** Nothing is matched by name or title. `people.name` is not unique, `works.title` is not unique, and (`title`, `publisher`, `year`) of an edition is only a business rule, not a key.
- `works`, `editions` and `people` also have a **slug**: the public identifier in the URL. It is generated by the server from the title or name with the rules in `docs/requirements.md` §6 (keep Unicode letters and digits, one hyphen for every other run, `-2`, `-3` … when taken, never `new` for an edition), is unique within its table and never changes after creation.
- `data/seed.json` contains no synthetic `id` or `slug` values. `npm run db:seed` creates them for every work, edition and person it inserts; nothing is matched by name or title.
- Types are limited to `text`, `integer` and `timestamp`, as requirements say.

## Tables

| Table | Columns | Keys and constraints |
| --- | --- | --- |
| `genres` | `id`, `key`, `name` | PK `id`; unique `key`; unique `name`. Fixed, seeded dictionary |
| `credit_roles` | `id`, `key`, `level`, `name`, `position` | PK `id`; unique `key`; `level` is `work` or `edition`; `position` comes from the array order in `data/seed.json`. Fixed, seeded dictionary |
| `people` | `id`, `slug`, `name`, `born`, `died`, `bio`, `photo_url` | PK `id`; unique `slug`; **no** unique `name` |
| `works` | `id`, `slug`, `title`, `original_title`, `year`, `original_language`, `synopsis` | PK `id`; unique `slug`; no unique `title` |
| `work_genres` | `work_id`, `genre_id` | PK (`work_id`, `genre_id`); both FKs |
| `editions` | `id`, `slug`, `title`, `publisher`, `year`, `language`, `isbn` | PK `id`; unique `slug`; `isbn` nullable and **not** unique |
| `edition_works` | `edition_id`, `work_id`, `position` | PK (`edition_id`, `work_id`); unique (`edition_id`, `position`) |
| `work_credits` | `work_id`, `person_id`, `role_id` | PK (`work_id`, `person_id`, `role_id`) |
| `edition_credits` | `edition_id`, `person_id`, `role_id` | PK (`edition_id`, `person_id`, `role_id`) |
| `users` | `id`, `email`, `password_hash`, `created_at` | PK `id`; unique `email`, stored lowercase |
| `user_roles` | `user_id`, `role` | PK (`user_id`, `role`); `role` is `curator` (later also `reader`) |
| `sessions` | `id`, `user_id`, `token_hash`, `expires_at`, `created_at` | PK `id`; unique `token_hash`; `user_id` FK; 30-day lifetime |

Composite primary keys on the join tables make a duplicate credit and a repeated work in one edition impossible at the database level, which is what the requirements' "unique together" rules ask for. No `ON DELETE CASCADE` anywhere: catalog rows are create-only; session rows are deleted on logout, and expired session rows may remain until a cleanup strategy is chosen.

## Relations

- **Work → authors:** `work_credits` with a `work`-level role (`author` in the MVP), joined to `people`.
- **Edition → Contents:** `edition_works` ordered by `position` (1, 2, 3 …).
- **Edition → Cast:** `edition_credits` with an `edition`-level role, joined to `people`, grouped by `credit_roles.position` (dictionary order).
- **Work → genres:** `work_genres`.
- **User → roles:** `user_roles`; **user → sessions:** `sessions`.

## Rules that must hold

- A work credit uses a `work`-level role and an edition credit uses an `edition`-level role. Enforced in the create-edition service (the composite keys cannot see `credit_roles.level`).
- A work has at least one `author` credit and at least one genre; an edition has at least one Contents row. Edition credits are optional. Enforced in the create-edition service, inside the transaction.
- A person may hold several roles. Within one work or edition the same person–role pair is unique — the composite primary keys enforce it, and the create-edition service pre-checks it to return `400` with a `fields` path. On a work the only role is `author`; an edition may carry several different edition-level roles for the same person.
- An edition with the same title, publisher and year as an existing one is rejected (`409`, with a link to the existing edition). Compared after trimming whitespace, case-sensitively; an empty publisher counts as absent. Checked in the service, not by a constraint.
- An ISBN is stored normalised (digits, `X` for ISBN-10) after check-digit validation, and may repeat across editions.
- A slug is unique within its table and never changes.

## Derived, never stored

- **Cover** of an edition: built from the ISBN with the Open Library Covers API; placeholder when there is no ISBN or no cover is found.
- **Edition count** of a work, on the catalog and work pages.
- **Filmography** on the person page: work credits under "Works", edition credits under "Editions" grouped by role.
- **Initials placeholder** for a person without a photo, or when the photo URL fails to load.
